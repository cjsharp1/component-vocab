Button group

A set of related buttons or links shown together, such as a primary and a secondary call to action. It groups them visually and, when useful, with role="group", but adds no keyboard behavior of its own.

Also known as
Toolbar. In design systems: Button Group (MUI, shadcn/ui); Button group (Bootstrap, Polaris); Toolbar (Fluent UI); Toolbars (Apple HIG)
Semantic element
<div>, optionally with role="group"
Native HTML
<div role="group">
ARIA pattern
Toolbar (only if roving tabindex is needed)
Research note
A CTA pair is not a toolbar

Usage Notes

  • Calls to action usually go somewhere, so make them <a href> links styled as buttons. Use <button> only for actions on the current page.
  • Don't add role="toolbar". The ARIA Authoring Practices toolbar pattern expects a single tab stop with arrow-key movement, which a pair of calls to action doesn't need. Each item stays in the normal tab order.
  • Add role="group" with aria-label only when the grouping tells screen reader users something, such as a set of actions for one item in a list.
  • Keep the source order the same as the visual order so reading and focus order match (WCAG 1.3.2, 2.4.3). Don't reverse the buttons with CSS alone.
  • For choosing one of several options, use a Segmented control. For several buttons that each stay pressed, use Toggle buttons.
