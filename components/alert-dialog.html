Alert dialog

A Dialog that interrupts the user to confirm or acknowledge something important, such as deleting a file. It stays open until the user picks a response.

Also known as
Confirm dialog. In design systems: Popconfirm (Ant Design); Alert Dialog (Radix Themes, shadcn/ui); Alerts (Apple HIG)

HTML Outline

A high-level skeleton showing the semantic elements and ARIA this component uses. Illustrative, not production markup.

<dialog role="alertdialog" aria-labelledby="a-title" aria-describedby="a-desc">
  <h2 id="a-title">Delete file?</h2>
  <p id="a-desc">This can't be undone.</p>
  <button>Cancel</button>
  <button>Delete</button>
</dialog>

Usage Notes

  • Use an Alert dialog only when the user must respond before going on, such as confirming a deletion. For information that needs no decision, use an Alert or a Toast.
  • Open it with showModal() and set role="alertdialog", with aria-labelledby pointing at the title and aria-describedby at the message, so screen readers announce both.
  • Move focus into the dialog when it opens. The APG suggests focusing the least destructive action, usually Cancel, when the confirm action can't be undone.
  • Label buttons with the action ("Delete", "Keep editing") rather than "Yes" and "No", so the choice makes sense without rereading the message.
  • Escape should close it as Cancel, and focus should return to the control that opened it.
